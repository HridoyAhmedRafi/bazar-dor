# AGENTS.md

## Project

BazarDor is a single Next.js 16 App Router app (`src/`) for comparing Bangladeshi market prices. TypeScript is strict; imports use `@/*` -> `src/*`.

## Commands

```bash
npm install          # npm + package-lock.json
npm run dev          # next dev
npm run build        # next build
npm run start        # production server
npm run lint         # eslint over the repo
```

Typecheck (no script exists): `npx next typegen && npx tsc --noEmit`.
`tsc` alone fails because `LayoutProps` and other route types are generated by Next. If `.next/types` is stale after deleting a route, remove `.next` and regenerate.

There are no test files or test runner, and no CI, formatter, or pre-commit config. Do not invent test commands.

## Architecture

- Routes: `/`, `/category/[categoryId]`, `/details/[detailsId]`, `/profile`, plus `(auth)/sign-in` and `(auth)/sign-up`.
- Prices and categories come directly from the public API `https://openapi.programming-hero.com/api/bazardor/...`; there is no local data layer. Server Components fetch it directly.
- List/category endpoints return `IMarquee` (`src/types/marquee-links-type.ts`). The product-details endpoint returns a different shape with a `markets` array and is typed inline in the details page; do not reuse `IMarquee` there.
- Layout files: `src/components/home` for page sections, `src/components/shared` for navbar/footer/shared UI, `src/components/user-session` for auth controls.
- The root layout always renders `Navbar`, including async `Marquee` and `NavLinks` fetches, plus `Footer`; failures in those API calls affect every page.

## Auth

- Better Auth server config: `src/lib/auth.ts`; catch-all handler: `src/app/api/auth/[...all]/route.ts`; browser client: `src/lib/auth-client.ts`.
- MongoDB database name is hardcoded as `bazar-dor`. Required env keys: `MONGODB_URL`, `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`. A local `.env` exists but is gitignored; there is no `.env.example`.
- Route protection lives in `src/proxy.ts` (Next 16's `proxy.ts`, not `middleware.ts`). Its matcher currently protects `/profile` and `/details/:path`; add new protected routes to that matcher.
- Email/password has `autoSignIn: false`; sign-up intentionally redirects to sign-in instead of logging the user in.
- Known quirk: `auth-client.ts` creates a client with `BETTER_AUTH_URL`, then exports helpers from a second `createAuthClient()` with no options. The exported helpers do not currently use that base URL.

## UI Conventions

- Styling is Tailwind CSS v4 plus daisyUI, loaded via `@plugin "daisyui"` in `src/app/globals.css`. `@heroui/*` is installed but not used; don't assume HeroUI is configured.
- User-facing text is Bengali. Format prices, counts, and percentages with `toLocaleString("bn-BD")`, and dates with `timeZone: "Asia/Dhaka"`.
- Product `image` and category `icon` values from the API are emoji strings rendered as text, not image URLs.
- Add `"use client"` only for interactive components (forms, menus, sorting). Most pages and data-fetching components are Server Components.
- React Compiler is enabled in `next.config.ts`; the root layout also loads Noto Serif Bengali and sets `data-theme="light"`.
